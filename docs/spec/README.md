# Specification (design intent)

- **Audience:** architects / contributors who want the intended design
- **Deployment target:** read-only
- **Authority:** **spec — NON-AUTHORITATIVE for shipped behavior**
- **Edit rule:** describes intent; never cite as proof of how the system behaves

The Functional Specification Document here records the workbench's *intended* design. It is
**not** the source of truth for what the code actually does — it is known to diverge (it
still describes a Pi Zero W; the production build is a Pi 4B + Argon One M.2).

For real behavior, read the code (`pi/`) and the operator docs (`docs/`). See
[`../../AUTHORITY.md`](../../AUTHORITY.md).
